# Demo Failure Recovery

## Purpose
Keep a truthful, functional demo when a dependency fails; do not disguise fallback output as a live investigation.

## Detection and observable behavior
| Symptom | Check | Response |
|---|---|---|
| No patient found | Tenant, seed version, patient ID, search index | Restore seed snapshot; retry search once, do not invent patient |
| Hospital API unavailable | Health endpoint and service logs | Restart healthy service or switch to **clearly labeled** offline dataset viewer |
| Missing PDF/image | Asset manifest, checksums, URLs | Open structured source record; flag unavailable visual asset |
| Model timeout/rate limit | Retryable status, quotas, request IDs | Bounded backoff; cancel/mark partial rather than endless spinner |
| Tool retrieval fails | Tool args, auth scope, correlation ID | Retry idempotent read; display failed event; preserve partial evidence |
| Agent gives unsupported claim | Citation verifier | Suppress as verified finding; label unverified; re-run evidence check |
| Live stream interrupted | Last event cursor/sequence | Reconnect and rehydrate from persisted events; deduplicate |
| Wrong/empty contradiction | Dataset checksum, provenance, evaluator tests | Stop result reveal; run diagnostics, do not force expected conclusion |

## Recovery tiers
**Tier 1 — retry:** safely retry a bounded read request, retaining one audit trail. **Tier 2 — resume:** recover from persisted `run_id` and event cursor if API supports it. **Tier 3 — partial report:** accurately show gathered evidence and explain missing steps. **Tier 4 — recorded walkthrough:** use a previously verified and explicitly labeled replay, with original evidence links if available.

## Guardrails
- Never patch the database manually during a live investigation without restarting and disclosing it.
- Never transform a replay into purported real-time tool calls.
- Never expose a hidden answer-key report as generated by agents.
- Keep every failure and retry attributable to a request ID.
- Avoid indefinite loading: show a definite failed or degraded state if progress stops.

## Practice drills
Test API outage, missing asset, model timeout, malformed tool response, expired session, interrupted stream, and inconsistent data seed. Document expected UI, operator action, and recovery outcome for each.

## Definition of done
Every drill has an honest user-visible failure state; an operator can recover or switch modes without fabricating evidence; final UI clearly identifies whether the run was live, partial, or replayed.
