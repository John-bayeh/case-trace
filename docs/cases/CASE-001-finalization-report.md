# CASE-001 Finalization Report

Date: 2026-10-22

## Outcome

CASE-001 now uses the two manually supplied JPEG radiographs as curated reference
assets. The clinical record retains all three imaging studies and all three
radiology reports. `IMG-001-03` intentionally has no image asset and is served
through its report only.

The reference images are not examinations of the fictional CASE-001 patient.
They are presented as externally sourced educational/reference material associated
with the simulated radiology timeline.

## Original imaging problems

- The generator created three Pillow-drawn educational location diagrams.
- The diagrams were registered as image assets for all three studies, including
  the July study that only requires a report.
- The radiology PDFs described the attachments as educational diagrams, which was
  no longer accurate after the curated radiographs were supplied.
- The validator and regression tests assumed PNG assets and 26 total assets.

## Canonical case and manifest changes

- Case version advanced from `1.0` to `1.1`.
- `imaging_assets` changed from three entries to exactly two:
  `IMG-ASSET-001-01` and `IMG-ASSET-001-02`.
- `IMG-001-03`, its encounter/date/modality/report relationship, and its report
  remain unchanged except for the report wording that clarifies external
  reference-image status.
- Imaging asset MIME types are `image/jpeg`; dimensions are recorded in the
  canonical asset metadata.
- Manifest count is now `imaging_studies: 3`, `imaging_assets: 2`, with 25 total
  assets (23 PDFs and 2 images).
- Manifest SHA-256 and byte sizes were recalculated from the actual bytes.
- The evaluator answer key's dataset version and source checksums were updated
  as integrity metadata; expected findings and clinical answers were not changed.

## Generator and validation changes

`scripts/generate_case001.py` now:

- Generates structured records and PDFs deterministically.
- Copies the two curated local reference assets without downloading or drawing
  replacement images.
- Registers only the first two studies as image-bearing.
- Preserves report-only studies.
- Records source publication/panel provenance in the manifest.
- Avoids overwriting curated assets when output is the canonical repository.

`scripts/validate_case001.py` now validates the declared image MIME type rather
than requiring PNG specifically. The API schema and asset storage already
supported JPEG and optional imaging assets, so no migration or runtime schema
change was required.

## PDF, backend, and frontend changes

The three radiology PDFs remain present and readable. The first two now state
that an attached image is an externally sourced reference radiograph, not an
examination of the simulated patient. No underlying clinical finding, date,
report association, or clinical storyline was changed.

The existing backend asset endpoints serve JPEG content with the declared MIME
type and keep patient ownership and constrained-storage checks. The existing
frontend imaging component already renders a typed image asset and displays
`No image assets registered.` for a report-only study; no redesign or frontend
source change was necessary.

  JPEG MIME validation is supported and an empty asset collection renders a

contradiction. The finalization replay preserves those result-level metrics.
Anchor totals are not directly comparable to the prior 108-anchor report because
the dataset was versioned and the radiology document bytes/source hashes changed;
the evaluator still reports complete required-source coverage and exact
discovery.

## Remaining limitations and readiness

- The images remain external reference material and should not be described as
  patient-acquired studies.
- Visual compatibility is only a broad presentation check; no radiologist or
  independent clinical expert review was performed.
- The source figure's clinical history belongs to the publication, not to the
  fictional patient; CASETRACE's synthetic reports remain the authoritative
  simulated record.
- Full frontend browser/build checks were not changed by this data-only update.

CASE-001 is ready to serve as the multimodal quality reference for future case
authoring. CASE-002 generation was not started.
